# SUP 数据库迁移记录

本文档记录影响 `sup_` 表的生产迁移。所有迁移文件应优先放在 `sup-wiki/database/`，执行后在此登记。

## 记录规则

- 只记录已执行或计划执行的生产迁移。
- 同一个迁移文件如果分多次执行，需要分别记录执行时间和影响范围。
- 如果迁移影响小程序，必须同步更新 `sport_hacker/server/database/schema.md`。
- 如果迁移包含回填，必须记录影响行数。
- 生产数据库节点为 `hk_aliyun_ecs` / `8.217.233.65`，库名 `sport_hacker`。
- `sport_hacker` 仓库里的 SUP 表说明只能作为速查，不能替代本迁移记录。

## 状态说明

- `planned`：已准备迁移文件，尚未执行生产。
- `applied`：已执行生产。
- `partial`：部分执行，需要补充说明。
- `rolled_back`：已回滚或通过恢复脚本撤回。
- `superseded`：被后续迁移取代。
