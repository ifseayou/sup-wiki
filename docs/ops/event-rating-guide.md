# SUP Wiki 赛事星级与积分系数说明

本文档记录 SUP Wiki 当前赛事星级字段、页面展示口径和人工评级规则。后续新增赛事、导入成绩册、录入报名信息或修正赛事等级时，应按本文档执行，并在存在不确定证据时保守评级。

## 字段含义

赛事星级目前主要落在 `sup_events` 表：

- `star_level`：前台展示的赛事星级标签，例如 `五星`、`四星+`、`三星`。
- `score_coefficient`：积分权重系数，例如 `5`、`4.5`、`3`。同等名次或基础分下，系数越高，对积分排名影响越大。
- `source_scope`：赛事人员/成绩来源范围，例如 `全球`、`亚洲`、`全国`、`本省市`。
- `result_status`：成绩采集状态，不决定星级，只表示成绩数据完整度。

后台赛事编辑页选择 `star_level` 时，会通过 `src/lib/event-stars.ts` 自动带出默认 `score_coefficient`。

## 评级优先级

赛事评级不能只看营销标题，应按证据优先级判断：

1. 官方年度竞赛计划、公开招募计划、竞赛规程中明确的星级或等级。
2. 主办/主管单位与赛事名称是否命中官方赛事体系。
3. 赛事覆盖范围、参赛来源、是否为总决赛/分站、是否有官方成绩册。
4. 媒体报道、公众号文章、报名页等辅助信息。

如果官方计划和页面历史指南冲突，以最新官方计划为准；如果证据不足，保守评级并标记需要人工复核。

## 人工评级步骤

1. 读取赛事名称、年份、主办单位、承办单位、竞赛规程、成绩册、报名公告。
2. 优先匹配“2026-2029 官方计划优先映射”。
3. 未命中时，使用“通用评级矩阵”按赛事层级判断。
4. 设置 `star_level`、`score_coefficient`、`source_scope`。
5. 在 `description`、`result_source_note` 或后续独立 `rating_reason` 字段中记录评级依据。
6. 如证据冲突或影响积分权重明显，先保守评级，并标记人工复核。

## 需要人工复核的情况

- 名称写“国际”，但没有国际组织、国际组别或官方国际公开赛证据。
- 分站赛事借用了总决赛或整条联赛的高评级，但自身规程未明确同等级。
- 赛事名称过于泛化，例如“城市公开赛”“嘉年华”，没有主管单位或备案信息。
- 成绩册、报名页、数据库年份或赛事名称互相冲突。
- 同一个赛事可归入多个类别，且不同类别会导致积分系数变化。

## 与成绩/积分导入的关系

星级不决定成绩是否可导入。成绩导入后会写入 `sup_event_results`，积分导入后会写入 `sup_event_point_standings` 或年度积分相关表。星级和积分系数主要影响：

- 成绩查询的星级筛选。
- 赛事详情页和赛事列表的星级展示。
- 年度积分或后续排名规则中的权重解释。

录入成绩册时，如果赛事已存在，应优先沿用该赛事已有 `star_level`、`score_coefficient` 和 `source_scope`；只有在发现官方证据更明确或原值明显错误时才修正，并同步记录变更原因。
